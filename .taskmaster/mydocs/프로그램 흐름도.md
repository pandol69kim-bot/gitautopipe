```mermaid
flowchart TB

  Security --> Access["권한 확인"]

  RateLimit --> SecretCheck["필수 시크릿 확인"]
  SecretCheck --> Handler["명령 핸들러 실행"]
  Handler --> Format["결과 포맷"]
  Format --> AuditSuccess["감사 로그 success"]
  AuditSuccess --> Output["결과 출력"]

  Access -. 실패 .-> AuditFail["감사 로그 failure"]
  RateLimit -. 실패 .-> AuditFail
  SecretCheck -. 실패 .-> AuditFail
  Handler -. 실패 .-> AuditFail
  AuditFail --> Error["에러 종료"]
```

## 워크플로우 실행 흐름

```mermaid
flowchart TB
  Execute["executeWorkflow(workflowId, payload)"] --> Find["workflow 조회"]
  Find --> Context["실행 컨텍스트 생성<br/>executionId, triggeredAt, payload"]
  Context --> Loop["step 순차 실행"]

  Loop --> Step["executeStep"]
  Step --> Success["completed"]
  Step --> Failure["failed"]

  Failure --> Policy["errorHandling.strategy 확인"]
  Policy --> Continue["continue/retry"]
  Policy --> Stop["stop"]

  Success --> Next["다음 step"]
  Continue --> Next
  Stop --> Result["ExecutionResult 생성"]
  Next --> DoneCheck{"모든 step 완료?"}
  DoneCheck -->|아니오| Loop
  DoneCheck -->|예| Result
  Result --> History["history 저장"]
  History --> Return["결과 반환"]
```

## 해석 주의

CLI와 워크플로우는 현재 로컬 실행 흐름 기준으로 정상 동작합니다. 다만 일부 워크플로우 step은 실제 외부 API 호출이 아니라 완료 메시지를 반환하는 형태입니다. 실제 GitHub, Claude, Notion, Vercel 라이브 연동 검증은 integration 모듈별 API 스모크 테스트를 별도로 실행해야 합니다.
