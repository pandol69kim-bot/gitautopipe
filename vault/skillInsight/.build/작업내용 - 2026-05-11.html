개요

node ./dist/cli/index.js deploy 명령이 실제 WebsiteDeployer를 통해 동작하도록 연결하고, 배포 완료 후 실제 URL 접속 확인까지 자동화했다.

주요 수정 내용

1. deploy 명령 실제 배포 연결

  • src/cli/commands.ts
  • 기존의 로그성 workflow emit 방식 대신 WebsiteDeployer를 직접 생성해 다음 순서로 실행하도록 변경
  • 소스 폴더 결정
  • 정적 사이트 빌드
  • Vercel 배포 생성
  • 배포 상태 폴링
  • 배포 URL 접근 검증
  • 완료 시 webhook 알림 전송
  • 결과 출력에 실제 배포 정보 포함
  • deploymentId
  • state
  • status
  • url
  • previewUrl
  • verificationStatus
  • verificationUrl
  • verificationHttpStatus
  • verifiedAt

    • 2. WebsiteDeployer 배포 로직 보강

  • src/workflows/website-deployer.ts
  • buildSite()가 .build 하위에 실제 산출물 생성
  • index.html
  • search-index.json
  • {slug}.html
  • deployToVercel()가 로컬 경로 문자열을 보내지 않고, .build 폴더 파일을 files 배열로 업로드하도록 수정
  • Vercel 에러 메시지를 중첩 객체에서도 읽을 수 있도록 개선
  • skipAutoDetectionConfirmation=1 query parameter 추가

    • 3. 배포 상태 대기 자동화

  • waitForDeploymentReady() 추가
  • Vercel 상태를 READY, ERROR, CANCELED까지 폴링하도록 구현
  • 관련 환경 변수 추가
  • DEPLOY_STATUS_MAX_ATTEMPTS
  • DEPLOY_STATUS_POLL_INTERVAL_MS

    • 4. 배포 URL 실제 접속 확인 자동화

  • verifyDeploymentUrl() 추가
  • READY 상태 후 실제 배포 URL에 GET 요청 수행
  • 검증 결과를 다음으로 분류
  • verified: 2xx 응답
  • protected: 401 또는 403 응답
  • unreachable: 반복 시도 후 실패
  • 관련 환경 변수 추가
  • DEPLOY_VERIFY_MAX_ATTEMPTS
  • DEPLOY_VERIFY_INTERVAL_MS

    • 5. protected 상태 처리

  • Vercel 배포 URL이 401/403을 반환하는 경우를 오류로 보지 않고 protected 상태로 처리
  • 이 경우 배포 자체는 성공으로 유지하고, 접근 보호 상태만 결과에 표시

    • 6. 보안 및 예시 환경 변수 정리

  • deploy 명령 필수 시크릿을 다음으로 정리
  • VERCEL_TOKEN
  • VERCEL_PROJECT_ID
  • .env.example에 배포 관련 선택 환경 변수 추가
